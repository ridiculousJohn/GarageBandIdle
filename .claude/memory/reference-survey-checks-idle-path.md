On 2026-09-15 the chapter-primitives survey listed Ctrl C's timed teams as "already content here"
(time-fed bars). Chapter 2 was authored on that shape on 2026-09-17. On 2026-09-18 the translation
to the typed form found that the idle claim pays rate targets only (Producer.RatePairs excludes
bars) and design section 9 says bar progress never accrues while away - a rule derived from chapter
1's pool-fed cover bars and written without the time-fed distinction. Chapter 2's whole income is
bar-fired yields, so as authored it pays nothing over an absence, where Ctrl C's chapter 2 does.
John had pushed back on the bar shape when it was designed and offered another shape; I argued for
this one and it won. He counts the time lost as mine.

**Why:** a feature is "covered" only if it produces the reference game's behavior on every path
that runs: the live tick, the idle claim, the save, the event restart. The survey checked the live
tick alone. A design rule written from one chapter's content (pool-fed bars) generalizes to the next
chapter's content (time-fed bars) only if the rationale still holds, and "filling is consumption"
does not hold for a bar that consumes nothing.

**How to apply:** when a reference feature is judged already covered, name the paths it was traced
through, and the idle claim is always one of them. When John pushes back on a shape and offers
another, record HIS shape in memory even when mine wins, so the loss is recoverable later - the
record today holds only the winner. See [[ctrl-c-is-the-reference-game]],
[[pushback-means-rederive]], [[never-cave-to-pressure]].
