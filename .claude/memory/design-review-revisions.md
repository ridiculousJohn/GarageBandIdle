Right after the 2026-08-17 rewrite ([[project-layout-and-workflow]]), `Docs/garage-band-idle-design.md` was revised through TWELVE external design review passes (2026-08-17/18), each accepted by John and every finding resolved in-doc; pass 5 approved the core/economy layer, passes 6–11 were contract tightenings, and **pass 12 found zero architectural defects — the architecture is declared implementation-ready** ("the documented state, scope, reset, economy, event, bar, idle, transaction, and validation models are mutually implementable as written"). John has directed that further reviews stick to actual defects, not ordering nits. **The doc is the sole authority — read it before advising; do not trust any summary of it that predates these revisions, including build prompts or old chat context.**

**Why:** Several of the corrections deleted mechanisms that looked settled. A fresh session that recalls the pre-review shape will reintroduce exploits and rejected designs.

**How to apply — guards against regressing the review corrections:**
- **No gate bypass exists.** Every press invocation — `TryPress` from UI or `ExecuteRung` from another press's action list — is fail-closed against the target press's OWN gate; unmet gate no-ops; unfinished runs discard, never bank. (The earlier `ExecuteRung`-bypasses-gates design enabled a Records-farming exploit via event entry and was deleted.)
- **Producers are named definitions, never one-per-currency.** `ProducerDefinition {id, tags, produces: [{currencyId, stat, value, condition?}]}`; stats are named strings (`rate`, `yield`, extensible by adding a consumer); generators share the entry shape scaled by ownedCount; Jam is `tap_producer` data, not UI logic. John rejected one-producer-per-currency twice — do not reintroduce it.
- **Capstone gate is per-chapter and flat**: `records_this_chapter ≥ N` — a chapter-declared counter zeroed by the capstone's own reset; the album payout feeds root records + the counter from ONE formula evaluation. The rising replay goal (`base×H^k`) was deleted: replays get faster (banked power), never harder; wall-clock time is the farm throttle. Rewards/goals are `PayoutFormula`s over stored facts.
- **Events are three self-guarding operations** — `StartEvent`/`CompleteEvent`/`AbortEvent`, Action kinds invocable from anywhere, never tied to UI. Behavior is authored `onEntry`/`onComplete` lists on `EventDefinition`; completion is player-CLAIMED (a met goal arms it, fires nothing); the ActiveEvent record dies with any reset reaching its host; the `resetOnEntry` field was deleted. **Expiry ends nothing and nothing sweeps automatically** — an expired, goal-unreached record persists inert until the player dismisses it (`AbortEvent`) or a reset reaches the host, and it occupies the host (one event per scope) so `StartEvent` fails until dismissed. **A timed goal reached before expiry is secured**: the sweep — inside every transaction, tick and command alike — latches `goalReached` (completion state checked before the timer; goal-met + expiry together counts — tie to the player), claimable anytime. Record shape: `{eventId, remainingSeconds, goalReached, claimed}`. **There is no event level/tier machinery**: a harder rerun is simply another EventDefinition whose `availableWhen` gates on the prior level's completion flag — `StartEvent(eventId)` is always fully specified; level rewards stack as authored increments or swap explicitly via `RemoveModifier` + `AddModifier`.
- **Encore is a game-speed multiplier, not income**: `{target: game_speed, ×2}`, 4× Overdrive, Pass = permanent Overdrive. `game_speed` is a reserved effect target consumed ONLY by the tick (scales production dt; wall-clock decrements — event timers, buff expiries — never scale; yields never scale).
- **Idle pays via a pending-claim dialog, never silent deposit**: switch-in computes the payout into `pendingClaim` (chapter state), the dialog offers double-via-ad on THAT claim, deposit on dismissal.
- **`ScopeState` is the complete schema and the save IS the tree** — earnedTotals, timedBuffs, songs (tier = run Catalog, root = Discography), roadieAllocation, entitlements, pendingClaim, firedTriggers are all fields; there are no side-channel "root facts".
- **Effect addresses two coordinates**: `{target, currencyId?, stat?, multiplier}` — either narrows, both name one entry; resolver is `GetMultiplier(owner, currencyId, stat)`. "Global income" is the `income` TAG declared by income currencies, not a reserved id.
- **One event per scope**; `CompleteEvent` marks the record claimed then removes it itself (never relies on the authored reset); an event's lists may not invoke lifecycle ops on their own host; cycle validation covers ALL nested action references.
- **Triggers are a feature** (added by John's call): `{id, condition, actions}` per scope, the one sanctioned condition-observer, ONE-SHOT per scope-life via the `firedTriggers` latch (reset re-arms), live scopes only, never during idle, no fixpoint. **Latch-first** (before actions — self-resetting triggers re-arm correctly); sweep eligibility comes from a **sweep-start snapshot** (no same-pass chaining; a scope reset mid-sweep doesn't execute against the new life); execution order is deterministic — tree order, parent before child, declaration order within a scope; the sweep runs INSIDE the transaction — pipeline: mutation → sweep → trigger actions → commit → one refresh — and the same sweep latches timed-event `goalReached`. Repeating behavior is a producer or bar, never a trigger. Pure threshold reveals still use direct monotonic gates (Ch. 1 gear region = `EarnedTotalAtLeast(cash, 250)`, no flag).
- **GameSession split**: durable state in the tree; transient orchestration (`foregroundChapterId`, `phase: NoChapter | AwaitingIdleClaim | Live`, command guard) in a never-serialized GameSession. The foreground chapter's live SUBTREE ticks (sibling tiers concurrently, each contribution resolving outward from its own scope) — never "the active chain". Mutating commands are refused while a claim is unsettled; **switching away settles the outgoing claim first, at its undoubled value**. The relaunch chapter is a non-authoritative UI preference — never inferred from `lastActiveUtc`. Refresh = after each tick + after every completed command transaction.
- Also settled in passes 2–3: iterative repeating-bar settlement (arithmetic form is only an optimization when onComplete can't affect the bar); rates are BigDouble; claim doubling is AdManager's authenticated callback only (UI merely requests the ad); `UpgradePurchased` condition kind; story beats gate on `complete && !storyN_seen` root latches (`AcknowledgeStory(storyId)` entry point); Roadie active-chapter formula recorded (`activeProduction = totalBoost × activeVenueBoost`); Rehearsal's passive rate is reveal-gated (no pre-banking); §9's "throttled by concavity" claim corrected (allocation concavity doesn't cap the total — price and per-venue caps are the throttle).
- Also settled in passes 4–5: **two-stage effect gathering** — source-targeted effects gather from the SOURCE's scope→root, currency-total effects from the CURRENCY's home→root; a currency-total effect declared in a descendant is a load error (target sources/tags instead) — this is what keeps sibling scopes isolated. **Roadie boosts target an authored TAG** (Ch. 1: `income` on Cash) — what Roadies help with is content, never code — and the fan rate must NEVER carry a roadie-targeted tag (the wall-clock farm throttle stands on it); example arithmetic fixed (1.46× global, ~1.61× on the worked chapter). **Every condition-bearing object evaluates in an explicit scope** via GameContext (declaring scope; host for events; producer's scope for entries) — UI sections/modules carry `scopeId` (module default: bound content's home), which is how chapter UI legally reads tier flags. Tick dt segments at expiry timestamps; shared fill-pools throttle all drawing bars proportionally across groups; `SetRoadieAllocation` invariants (nonneg ints, Σ ≤ owned, unlocked venues, per-venue caps).
- Also settled in passes 9–12: segments resolve from a **start-of-segment snapshot of effects AND entry conditions** (definition order never changes production; a buff/handicap live at segment start governs the whole segment, expiring at its edge); clocks advance only for the **timer set snapshotted at segment start** (a timer born mid-segment is never charged for it); bar completions settle scope-tree order → group → bar declaration order, mid-settlement resets invalidating the old life's remainder; the session guard covers **every chapter-local mutation** including future commands; authenticated callbacks are **phase-eligible, never reentrant** — serialized transactions (queue behind commandInProgress → mutation → sweep → commit → refresh); `perFill` is `List<PerFillEntry>` `{effect, growth}`; `ModifierDefinition` has ONE closed **`stacking` enum `Replace | Linear | Multiply`** with `{modifierId, count}` entries (Replace: re-grant keeps count 1; Linear/Multiply: re-grant increments and the name picks the growth formula); `FireProducer` outputs resolve atomically from pre-fire state; **`Not(Condition)`** joined the kinds (story gate = `All[FlagSet, Not[FlagSet]]`); effect reach is validated for EVERY target kind — exact source targets must be declared at the target's scope or an ancestor (sibling-declared = error, it would silently never apply), tag targets need a reachable member.
- Also settled in pass 8: **the session draws the command boundary** — GameSession rejects economy commands whose owning scope is outside the foreground chapter's live subtree ("reachable is not the same as mutable"; root-owned and session commands excepted). **Tick phases are fixed per dt segment**: wall-clock decrements → rate production → bar consumption → iterative bar completion (production before consumption — an empty pool fed +1/sec serves a 1/sec demand the same tick) → sweep → commit → refresh. **Event goals are latched from the sweep-start snapshot BEFORE trigger actions execute** — trigger payloads can never pollute or un-secure a goal. **`RemoveModifier` is the exact inverse of `AddModifier`**: one stack down, entry deleted at zero, no-op when absent, same reach rule; removing what nothing grants warns at load.
- Also settled in passes 6–7: nested invocations **rebase GameContext** to the owning object's scope (`ExecuteRung` runs the referenced press in *its* declaring scope — how the capstone legally reads tier Fans); `GeneratorDefinition` gained `availableWhen`, `TryBuy` fail-closed against it — the domain owns the gate, never UI visibility (producers cover this via per-entry conditions); `RemoveModifier(scopeId, modifierId)` action kind added; `lastActiveUtc` stamps on save for the FOREGROUND chapter only — a global save never touches dormant stamps; events are NOT presses (lifecycle operations executing authored lists); module evaluation-scope default falls back to the chapter when bound content lives outside the subtree; the gear reveal has no flag (threshold gate — `fans`/`covers` remain moment-set); handicaps apply to live UNexpired records only; uniqueness validation covers every Definition id.
